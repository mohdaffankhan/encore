# Contributing to Encore

Thanks for helping! Bug reports, ideas and pull requests are all welcome.

- **Bugs and ideas:** open an [issue](https://github.com/mohdaffankhan/encore/issues).
  For a bug, say which device and Encore version you have (the release
  you downloaded), and what you did before it happened.
- **Pull requests:** keep them focused on one change, and add or update
  the tests for it (see [Tests](#tests)). Every feature and fixed bug is
  listed with its tests in [FEATURES.md](FEATURES.md).

## Building

Requires [Flutter](https://docs.flutter.dev/get-started/install) 3.47 or
newer.

```sh
flutter pub get
flutter run -d windows   # or: -d linux, or an Android device
```

On Linux, install the build tools and libmpv first:

```sh
sudo apt install clang cmake ninja-build pkg-config libgtk-3-dev libmpv-dev
```

See [DESIGN.md](DESIGN.md) for how the app is put together and why.

## Tests

| What | Command |
|---|---|
| Unit + widget (offline, fast) | `flutter test test/unit test/widget` |
| Live checks against YouTube Music, Spotify, LRCLIB | `flutter test test/live` |
| End-to-end, real audio (desktop) | `flutter test integration_test/app_test.dart --dart-define=ENCORE_TEST=true -d windows` |
| End-to-end on Windows with real key presses | `powershell -File tool/windows_keyboard_check.ps1` |
| End-to-end on Android, with background playback | `sh tool/android_background_check.sh <device>` |
| Linux, in Docker | `docker build -t encore-linux-test tool/linux_test` then `docker run --rm -v "$PWD:/src" encore-linux-test` |
| Any release build | `encore --self-test` (plays a song, exits 0 or 1) |
| Frame timings | `flutter drive --profile --no-dds --no-uninstall --driver=test_driver/perf_driver.dart --target=integration_test/perf_test.dart -d <device>` |

`ENCORE_TEST` keeps the tests' likes, playlists, history and downloads
apart from your own.

> On a phone that has Encore installed, never run plain `flutter test` or
> `flutter drive`: at the end Flutter uninstalls the app by its id, which
> removes the real Encore and its library. The Android script above passes
> `--no-uninstall` and removes only the test app.

## Screenshots

The README's screenshots come from `integration_test/screenshots_test.dart`,
which shows each screen with real content:

```sh
flutter test integration_test/screenshots_test.dart --dart-define=ENCORE_TEST=true -d windows
# → build/screenshots/windows/readme/*.png
```

On Android, run it with `--no-uninstall` and save the output; then
`python tool/collect_screenshots.py <output> <folder>` rebuilds the PNGs.

## Linux packages

Made from the Linux release build, in `linux/packaging/`:

| Package | Made by | Files |
|---|---|---|
| `encore-linux-x64.tar.gz` | `make_tarball.sh` (the bundle + launcher, icons, metadata, `install.sh`) | `*.desktop`, `*.metainfo.xml`, `icons/`, `install.sh` |
| `encore-linux-x64.flatpak` | `flatpak-builder` with the tarball, plus libmpv built in | `flatpak/io.github.mohdaffankhan.Encore.yml` |
| AUR `encore-music-bin` | `makepkg` from the tarball | `aur/PKGBUILD` |

Releases ship the tarball for now. The Flatpak and AUR package aren't
released yet: GitHub Actions builds them only when the workflow is run by
hand. `tool/linux_release_check.sh <folder> [tar aur flatpak]` installs each
in a clean container (Ubuntu, Arch, Flatpak) and plays a song.

## Releasing (maintainer)

A release is only published after it has played music on real devices,
from the exact files people will download.

1. Set the version: `version:` in `pubspec.yaml`, `pkgver` in
   `linux/packaging/aur/PKGBUILD`, and a `<release>` in
   `linux/packaging/io.github.mohdaffankhan.Encore.metainfo.xml` (CI checks
   they agree). Commit, then tag:
   ```sh
   git tag v0.2.0 && git push origin v0.2.0
   ```
   GitHub Actions tests and builds everything and creates a **draft**
   release.
2. With the Android phone connected and Docker running:
   ```sh
   sh tool/release_check.sh v0.2.0 <adb-device-id>
   ```
   It downloads the draft's files, plays music with the APK on the phone,
   the Windows zip and installer on this PC, and the Linux tarball in a
   container, and publishes the release only if everything passes.

Android releases are signed with a key kept in repository secrets
(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`). To sign locally, put the same values in
`android/key.properties` (ignored by git). App icons are generated by
`python tool/icons.py .`.
